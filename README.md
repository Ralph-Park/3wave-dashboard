# 3-Wave Dashboard

금융 자산 투자용 대시보드 초안. 지표를 **큰 파도(거시) → 중간 파도(유동성·수급) → 작은 파도(종목 모멘텀)** 세 층으로 나눠 채점하고, 시장 전체의 투자 매력도와 권고 현금 vs. 투자 비중을 하나의 게이지로 보여준다.

> **이 대시보드는 투자 권유가 아니다.** 모든 임계값·가중치는 백테스트로 검증되지 않은 초기 가정값이며, 뉴스 중요도 산식은 휴리스틱이다.

---

## 1. 설계 원칙

| 원칙 | 구현 |
|---|---|
| 추정값 금지 | 수집 실패 지표는 `value: null`, `status: "no_data"` 로 남고 화면에 "데이터 없음 (사유: …)" 로 표시된다. 어떤 값도 추정·보간하지 않는다. |
| 출처 동반 | 모든 수치에 출처명·series ID·as-of·수집 시각·수집 경로가 붙어 화면에 표시된다. |
| 결측 재정규화 | 결측 지표는 종합 점수에서 제외되고 남은 지표의 가중치가 재정규화된다. 화면에 항상 "데이터 커버리지 N/M" 이 표시된다. |
| 커버리지 하한 | 커버리지가 60% 미만이면 종합 점수 대신 **"데이터 부족 — 판단 유보"** 를 표시한다. |
| 뉴스는 참고자료 | 뉴스는 종합 점수에 **자동 반영되지 않는다.** 사용자가 `manual_inputs.json` 에 직접 점수를 넣은 경우에만 반영된다. |
| 하드코딩 금지 | `index.html` 에는 어떤 지표 값도, 어떤 기사도, 어떤 임계값도 들어 있지 않다. 전부 JSON에서 읽는다. |

## 2. 파일 구성

```
Dashboard/
├── fetch_data.py        # FRED 수치 수집 → data.json
├── fetch_news.py        # Google News RSS 뉴스 수집 → news.json
├── fetch_leaders.py     # 주도주(RS 모멘텀) 자동 선정 → leaders.json (가상환경 필요)
├── analyze_leadlag.py   # 지표 점수 vs 이후 수익률 선행성 측정 → leadlag.json (연구용)
├── compare_weights.py   # 가중치안을 20년/5년 두 구간에서 동시 평가 (연구용)
├── scoring_config.json  # 임계값·가중치·비중매핑·뉴스 키워드 (유일한 튜닝 지점)
├── data.json            # 수치 (값/출처/series ID/as-of/수집시각/status)
├── leaders.json         # 주도주 선정 결과 + 선정 근거
├── leadlag.json         # 선행성 측정 결과
├── news.json            # 지표별 뉴스 목록 + 중요도 점수
├── manual_inputs.json   # 수동 입력 (초기값 전부 null)
├── index.html           # 대시보드 (단일 파일, 외부 의존성 0)
├── start.sh             # 서버 실행 + 브라우저 열기
└── README.md
```

## 3. 실행 방법

### 브라우저로 열기

```bash
cd Dashboard && ./start.sh
```

로컬 HTTP 서버를 띄우고 기본 브라우저로 대시보드를 연다. 이미 떠 있으면 새로 띄우지 않고 그 주소로 열기만 한다. 포트를 바꾸려면 `./start.sh 9000` 처럼 인자를 준다.

```bash
pkill -f 'http.server 8765'     # 서버 끄기
```

주소는 **http://localhost:8765/index.html** 이다. 서버가 떠 있는 동안에는 브라우저 북마크로 바로 열어도 된다.

> `index.html` 을 더블클릭해 `file://` 로 열면 **동작하지 않는다.** 브라우저 보안 정책(CORS)이 로컬 JSON 읽기를 막기 때문이다. 이 경우 화면에 안내 메시지가 뜬다. 반드시 `start.sh` 로 열 것.

Claude Code 의 미리보기 패널을 쓴다면 `.claude/launch.json` 에 `3wave-dashboard` 설정이 들어 있다.

### 데이터 갱신

```bash
cd Dashboard
python3 fetch_data.py      # data.json 생성 (약 30초)
python3 fetch_news.py      # news.json 생성 (40~60분, RESOLVE_LIMIT=0 이면 5~10분)
```

갱신 후에는 브라우저를 새로고침하면 된다. 서버를 다시 띄울 필요는 없다.

주도주 자동 선정까지 쓰려면 가상환경이 한 번 필요하다 (`fetch_leaders.py` 만 외부 라이브러리를 쓴다).

```bash
cd Dashboard
python3 -m venv .venv
.venv/bin/python -m pip install yfinance pandas lxml requests
.venv/bin/python fetch_leaders.py      # leaders.json + manual_inputs.json 갱신 (약 6분)
python3 fetch_news.py                  # 선정된 종목의 조건별 뉴스 수집
```

특정 지표의 뉴스만 다시 받으려면 키를 인자로 넘긴다.

```bash
python3 fetch_news.py cpi fed_stance
```

이 경우 기존 `news.json` 을 읽어 **지정한 지표만 갱신하고 나머지는 그대로 보존**한다 (덮어쓰지 않는다).

## 4. API 키 설정

**키가 없어도 전부 동작한다.** 아래는 전부 선택 사항이다.

| 환경변수 | 용도 | 없을 때 |
|---|---|---|
| `FRED_API_KEY` | FRED 공식 API 사용 | 키가 필요 없는 공개 CSV 엔드포인트 `fredgraph.csv` 로 자동 폴백. 동일한 데이터. |
| `NEWSAPI_KEY` | Google News RSS 실패 시 NewsAPI 폴백 | 폴백 건너뜀 (사유가 `news.json` 의 `errors` 에 기록됨) |
| `BING_NEWS_KEY` | 2차 뉴스 폴백 | 동일 |

```bash
export FRED_API_KEY="발급받은키"
```

키는 **하드코딩하지 않는다.** 스크립트는 환경변수만 읽으며, 키가 없으면 그 사실을 `data.json` 의 `fetch_environment` 와 `news.json` 의 `meta` 에 기록한다.

### 알려진 함정: FRED와 User-Agent

`fred.stlouisfed.org` 는 **브라우저를 사칭한 User-Agent(`Mozilla/...`)로 오는 요청에 응답하지 않고 연결을 끊는다.** `fetch_data.py` 는 FRED 요청에 한해 `urllib` 기본 User-Agent 를 쓴다 (`FRED_HEADERS = {}`). 이 코드를 고칠 때 UA를 "브라우저처럼" 바꾸면 전 지표가 타임아웃으로 결측 처리되니 주의할 것.

## 5. 지표별 출처 표

### 큰 파도 (가중치 50%, 채점 지표 2개 균등 = 각 25%)

| 지표 | 소스 | Series ID | 계산 |
|---|---|---|---|
| 미국 소비자물가 (CPI) | FRED | `CPIAUCSL` (+ `CPILFESL` 병기) | YoY = 최신월 / 12개월 전 같은 달 − 1. 3개월 연율 = (최신월/3개월 전)^4 − 1. 가속도 = 3개월 연율 − YoY |
| 미국 실업률 | FRED | `UNRATE` | 수준, 12개월 변화, 12개월 저점 대비 상승폭, Sahm rule 갭 |

#### 실업률 임계값 (2026-09-28 조정)

| 구성요소 | 가중치 | 임계값 | 상한 |
|---|---|---|---|
| 실업률 수준 | 0.30 | ≤3.6→0 · ≤4.4→**+1** · ≤5.2→0 · ≤6.0→−1 · 그외→−2 | +1 |
| 12개월 변화 | 0.25 | ≤−0.5→**+2** · ≤−0.1→+1 · ≤0.2→0 · ≤0.5→−1 · 그외→−2 | +2 |
| 12개월 저점 대비 상승폭 | 0.15 | ≤0.0→+1 · ≤0.2→0 · ≤0.5→−1 · 그외→−2 | +1 |
| Sahm rule 갭 | 0.30 | ≤0.0→+1 · ≤0.20→0 · ≤0.49→−1 · 그외→**−2**(트리거) | +1 |

**왜 바꿨나.** 이전에는 '12개월 저점 대비 상승폭'과 'Sahm 갭' 두 개만 보았고 둘 다 상한이 +2였다. 그래서 **실업률이 사이클 저점에 있기만 하면 +2가 나왔다.** 종합점수 시계열을 역산해보니 2022년 9월(실업률 3.6%, CPI 8.2%, 6개월간 금리 +2.75%p) 구간이 **54.2점** 으로 중립 이상이 나왔다 — 실업률의 +2가 CPI의 −2를 그대로 상쇄했기 때문이다.

사이클 저점의 낮은 실업률은 강세 신호가 아니라 경기 후반 신호에 가깝다. 그래서:

- **수준을 언덕 모양으로** 본다. 3.6% 이하 저점권은 "더 좋아질 여지가 없는" 구간이라 0점이다.
- **12개월 방향**을 넣었다. 높은 실업률에서 뚜렷하게 내려오는 회복 국면만 +2를 받는다.
- **'저점 유지' 항목들의 상한을 +1로** 낮췄다.

조정 후 역산 시계열의 구간 평균:

| 구간 | 조정 전 | 조정 후 |
|---|---|---|
| 2022 약세장 (1~10월) | 2022-09 단독 54.2 | **39.1** (구간 최저) |
| 2023 회복 | — | 47.9 |
| 2024 | — | 47.0 |
| 2025 | — | 49.6 |
| 2026 | — | 54.9 |

5년 구간에서 실업률 점수 분포는 `0` 146회 / `+1` 92회 / `−1` 23회다.

> **부작용 — 실업률은 이제 +2를 받을 수 없다.** 네 구성요소의 가중 최대값이 1.25라 반올림해도 +1이 상한이다. 그 결과 종합점수의 이론상 최대치가 100 → **93.75** 로 내려간다 (투자 비중 최상단 구간 80–100 은 여전히 도달 가능). 고용을 "매수 근거"가 아니라 "위험 신호"로 보는 설계이며, 되돌리려면 `scoring_config.json` 에서 `level_pct`·`sahm_gap_pp` 의 상한을 +2로 올리면 된다.
>
> 이 조정은 **한 사이클(2021–2026) 관찰에 근거한 것이고 백테스트가 아니다.** 해당 구간에 실제 침체가 없어 −2 사례가 한 번도 나오지 않았다.

### 중간 파도 (가중치 50%, 채점 지표 6개 균등 = 각 8.33%)

| 지표 | 소스 | Series ID | 계산 | 채점 |
|---|---|---|---|---|
| 연준 스탠스 | FRED | `DFEDTARU` (+ `FEDFUNDS`) | 최근 6개월 정책금리 변화 | ○ |
| 연준 대차대조표 | FRED | `WALCL` | 13주 / 52주 변화율 | ○ |
| 지급준비금 | FRED | `WRESBAL` | 13주 변화율 | ○ |
| 순유동성 | FRED (계산값) | `WALCL − WTREGEN − RRPONTSYD` | 4주 / 13주 변화율 | ○ |
| 재무부 일반계정 (TGA) | FRED | `WTREGEN` | 4주 / 13주 **증감액($B)** | ○ |
| 역레포 잔고 (RRP) | FRED | `RRPONTSYD` | 4주 / 13주 **증감액($B)** | ○ |

**단위 정규화:** `WALCL`·`WRESBAL`·`WTREGEN` 은 백만 달러, `RRPONTSYD` 는 십억 달러 단위다. 순유동성 계산 전에 전부 **십억 달러**로 맞춘다. 이 단위 차이를 놓치면 순유동성이 1000배 어긋난다.

**TGA·RRP 채점과 중복 계산.** 두 항목은 순유동성(`WALCL − TGA − RRP`) 산식에 이미 들어가 있어서 따로 채점하면 같은 유동성 신호를 두 번 세게 된다. 그럼에도 개별 채점하도록 설정했으므로, 중간 파도 6개 중 3개(순유동성·TGA·RRP)가 사실상 같은 흐름을 보고 있다는 점을 감안해야 한다. 각 카드에 이 경고가 표시된다. 되돌리려면 `scoring_config.json` 에서 두 지표의 `role` 을 `"component"` 로 바꾸고 `scoring.components` 를 비우면 된다.

**퍼센트가 아니라 증감액($B)으로 채점하는 이유.** RRP 잔고는 현재 $0.5B 수준까지 내려와 있어 퍼센트 변화가 −90%처럼 극단적으로 튄다. 단위가 살아 있는 절대 증감액으로 채점해야 "실제로 얼마가 풀렸는가"를 볼 수 있다. TGA 도 같은 기준으로 맞췄다.

### 종합점수 시계열 (역산)

게이지 카드 안에 종합점수 추이 차트가 붙는다. 주간 그리드로 최근 20년, 1,044개 시점이다.

**만드는 방법** — `fetch_data.py` 가 각 시점까지 잘라낸 원자료로 지표를 다시 계산해 `data.json` 의 `metrics_history` 에 담고, 화면이 여기에 **라이브 점수와 똑같은 채점 엔진**을 적용해 종합점수를 만든다. 점수화를 파이썬이 아니라 화면에서 하는 이유는, 두 벌의 채점 코드를 두면 언젠가 어긋나기 때문이다.

**발표 시차** — 각 시점에서 "그날 실제로 알 수 있었던" 값만 쓰도록 시리즈별 발표 시차를 뺀다 (`composite_history.publication_lag_days`).

| 시리즈 | 시차 | 근거 |
|---|---|---|
| `CPIAUCSL` / `CPILFESL` | 45일 | 8월 CPI 는 9월 중순 발표 |
| `UNRATE` | 38일 | 고용보고서는 익월 첫 금요일 |
| `WALCL` / `WRESBAL` / `WTREGEN` | 3일 | 수요일 기준, 목요일 공표 |
| `DFEDTARU` / `RRPONTSYD` | 2일 | 일별 |

시차를 빼지 않으면 미래 정보가 섞인다. 다만 이 때문에 **차트의 마지막 점은 상단 게이지와 값이 다르다** — 게이지는 시차 없이 최신 자료로 계산하기 때문이다. 화면에 그 차이를 명시한다.

> **이 차트로 전략을 검증하면 안 된다.**
> - 과거에 이 대시보드가 실제로 표시했던 점수가 아니라, **지금의 원자료와 지금의 임계값**으로 다시 계산한 값이다.
> - CPI·실업률은 사후 개정된다. 과거 구간은 "개정된 값"이라 당시 실제로 보였던 숫자와 다르다.
> - 임계값이나 가중치를 바꾸면 과거 구간 전체가 함께 바뀐다.
>
> 개정의 영향을 받지 않는 진짜 기록이 필요하면, 실행할 때마다 그날의 점수를 따로 적립하는 로그를 추가해야 한다 (현재는 없다).

커버리지가 60% 미만인 시점은 점을 찍지 않고 비워 둔다.

---

### 차트 기간 토글

지표 카드의 차트와 종합점수 차트는 **20년 / 10년 / 5년 / 3년 / 1년 / 6개월 / 3개월** 로 기간을 바꿀 수 있다. 기본값은 1년이다.

- **개별** — 카드 차트 아래 버튼을 누르면 그 카드만 바뀌고 `개별` 배지가 붙는다.
- **전체 일괄** — 화면 상단 `차트 기간` 버튼을 누르면 모든 차트가 바뀌고 **개별 지정은 모두 해제된다.**
- 이미 전역과 같은 기간을 개별로 누르면 개별 지정이 풀린다.

차트 아래 캡션에 표시 구간·관측치 수·최소/최대·구간 등락률이 함께 나온다.

`data.json` 의 `history` 는 **20년치**를 담는다. 일별 시리즈(`DFEDTARU`, `RRPONTSYD`)는 5년이면 1,300개가 넘으므로 균등 솎아내기로 400개 이하로 줄이되 최신 관측치는 항상 남긴다. 월별 지표(CPI·실업률)는 5년이 60개라 3개월 구간에서는 점이 4개뿐이다 — 원자료가 월 단위라 그 이상 촘촘해질 수 없다.

### 작은 파도 (가중치 0%, 시장 종합 점수 미반영)

4개 조건(캐파 공백 해소 / 공급처 확정 증설 완료 / 가격 결정권 발생 / 큰 테마의 병목 위치)은 재무 API만으로 자동 판정할 수 없다. 자동화되는 범위는 **후보 종목 선정까지**다.

```
[자동] RS 모멘텀 스크리닝 → 시장별 상위 5종목 → manual_inputs.json 갱신
[자동] 후보별 × 조건별 뉴스 수집
[수동] 뉴스를 읽고 4개 조건 체크          ← 자동화 불가
```

#### 주도주 자동 선정 (`fetch_leaders.py`)

```bash
.venv/bin/python fetch_leaders.py              # 미국 + 한국
.venv/bin/python fetch_leaders.py --market KR  # 한쪽만
.venv/bin/python fetch_leaders.py --dry-run    # manual_inputs.json 을 건드리지 않고 결과만 확인
```

**유니버스**

| 시장 | 소스 | 키 | 1차 필터 |
|---|---|---|---|
| 미국 | Nasdaq Stock Screener API (NASDAQ + NYSE) | 불필요 | 시가총액 100억 달러 이상, 상위 1,000종목 |
| 한국 | 네이버 금융 모바일 API (시가총액 순위) + KRX KIND (업종·주요제품 보강) | 불필요 | 코스피·코스닥 각 시총 상위 400종목, 스팩·우선주 제외 |

가격은 **yfinance** 로 배치 다운로드한다. 한국 종목도 `.KS` / `.KQ` 접미사로 받는다.

> **유니버스를 왜 미리 줄이는가.** 처음에는 KIND 전 종목(4,117개)을 내려받았는데 Yahoo 레이트리밋에 걸려 **517종목이 데이터 없음, 수백 건이 `YFRateLimitError`** 로 빠졌다. 그 잔여물로 만든 순위는 주도주가 아니라 "레이트리밋을 피해 살아남은 종목"이었다(상위권이 전부 중소형주로 채워짐). 시가총액 상위로 먼저 줄이면 요청 수가 1/5로 줄어 레이트리밋을 피하고, 애초에 주도주가 있을 법한 구간만 본다.

**한국 우선주 제외** — 네이버 시총 순위에는 우선주(삼성전자우 등)가 섞여 들어온다. KRX 종목코드 6번째 자리가 `0` 이어야 보통주이므로 그 규칙으로 거른다.

**`pykrx` 는 쓰지 않는다** — KRX 내부 API 가 `LOGOUT`(HTTP 400)을 반환해 빈 결과만 돌려준다. 시도했으나 동작하지 않았다.

**순위 모집단 — 시가총액 상위 100종목**

유니버스를 다 받은 뒤, **순위는 시가총액 상위 100종목 안에서만** 매긴다 (`rank_universe_top_by_cap`).

> **왜 제한하는가.** 제한 없이 돌렸더니 한국 상위권이 가온전선·금호건설·RF머트리얼즈·빛과전자·KBI메탈 같은 소형 테마주로 채워지고, 삼성전자는 #67, SK하이닉스는 #37 이었다. 버그가 아니라 산식의 성질이다 — 초과수익 백분위는 변동성이 큰 소형주에 구조적으로 유리하다. 가중치를 바꾸거나 필터를 풀어도 (실제로 4가지 조합을 다 돌려봤다) 대형주는 상위권에 오지 못했다. 통상적 의미의 "주도주"를 잡으려면 **모집단 자체를 대형주로 좁히는 수밖에 없다.**

**RS 모멘텀 산식**

각 기간의 초과수익을 구한 뒤 **유니버스 내 백분위로 변환**해서 가중평균한다.

```
초과수익(기간) = 종목 수익률(기간) − 벤치마크 수익률(기간)
백분위(기간)   = 필터 통과 종목 중 그 초과수익의 교차단면 순위 (0~100)
RS 점수        = Σ 백분위(기간) × 가중치        (3M 0.4 / 6M 0.3 / 12M 0.3)
```

벤치마크는 미국 `SPY`, 한국 `^KS11`(KOSPI) 이다.

> **왜 백분위인가.** 처음에는 초과수익을 그대로 가중합했는데, 스핀오프로 가격 시계열이 왜곡된 종목(12개월 수익률 +1807%로 계산됨) 하나가 순위를 통째로 지배했다. 백분위로 바꾸면 그 종목은 해당 기간에서 100분위를 받을 뿐 다른 기간의 부진을 상쇄하지 못한다. 액면병합·분할·상장폐지 후 재상장 등에도 같은 문제가 생기므로 백분위 방식을 기본으로 둔다.

**추세 필터** — 아래를 모두 통과해야 후보가 된다.

- 200일 이동평균 **위**
- 최소 252거래일 이상의 가격 이력
- 52주 신고가 대비 낙폭 **50%** 이내
- 최근 60일 평균 거래대금: 미국 5,000만 달러 / 한국 100억 원 이상

> **낙폭 필터를 왜 50%로 느슨하게 두는가.** 처음엔 30%였는데, SK하이닉스(−36.4%)와 삼성전기(−38.9%)가 **200일선을 각각 +35.9% / +53.0% 위에서 달리고 있는데도** 탈락했다. 고변동 주도주는 크게 오르고 크게 조정받는다. 추세가 깨졌는지는 200일선 필터가 판정하게 두고, 낙폭은 극단적인 경우만 거르도록 느슨하게 둔다.

전부 `scoring_config.json` 의 `leaders` 섹션에서 조정한다. `top_n_per_market` 으로 선정 개수를 바꾼다.

**레이트리밋 대응** — 청크 100종목씩 나눠 받고 사이에 1.5초 쉰다. 청크 수신량이 절반에 못 미치면 레이트리밋으로 보고 20초→40초 백오프 후 재시도한다. 받은 가격은 `.cache/` 에 날짜별로 저장되어 같은 날 재실행은 즉시 끝난다 (`--no-cache` 로 무시).

**커버리지 가드** — 유니버스 대비 실제 가격을 받은 비율이 **85% 미만이면 해당 시장의 순위를 발표하지 않는다.** 훼손된 유니버스로 만든 순위는 주도주가 아니기 때문이다. 보류되면 화면에 사유가 표시되고 `manual_inputs.json` 도 건드리지 않는다.

**실행 시간 주의.** 뉴스 수집량은 `종목 수 × 4개 조건 × 키워드 4개` 로 늘어난다. 현재 설정(시장당 5종목)이면 10종목 × 4조건 = 뉴스 패널 40개이고, 거시 지표 9개를 합쳐 총 49개 키다. **전체 수집에 40~60분이 걸린다.** 병목은 RSS 검색이 아니라 Google News 리다이렉트 URL 해석(기사당 요청 2회)이다.

일상적인 갱신은 URL 해석을 끄면 5~10분으로 줄어든다. 링크는 Google News 리다이렉트로 남지만 브라우저에서는 정상적으로 원문으로 이동한다.

```bash
RESOLVE_LIMIT=0 python3 fetch_news.py     # 원문 URL 해석 생략 (가장 빠름)
RESOLVE_LIMIT=3 python3 fetch_news.py     # 지표당 상위 3건만 해석 (절충)
python3 fetch_news.py                     # 기본값 6건
```

```bash
RESOLVE_LIMIT=2 python3 fetch_news.py     # 지표당 원문 URL 해석을 2건으로 제한 (기본 6)
```

#### 종목명과 검색어 정리

Nasdaq 스크리너의 종목명에는 `Common Stock`, `Class C`, `Inc.`, `(new)` 같은 증권 종류 표기가 붙는다. 그대로 두면 뉴스 검색어가 오염되므로(`"Dell Technologies Inc. Class C Common Stock pricing power"`) 회사 이름만 남긴다.

한국 종목은 `000500.KS` 같은 코드로는 기사를 찾을 수 없다. `fetch_leaders.py` 가 후보마다 `search_ticker` 를 넣어주고(미국은 티커, 한국은 한글 회사명), `fetch_news.py` 가 검색 템플릿의 `{ticker}` 자리에 그 값을 쓴다.

#### 관련성 필터 (작은 파도 전용)

**회사 이름이 제목에 없는 기사는 그 종목의 근거가 될 수 없다.** 종목별 뉴스는 제목에 회사명·티커가 실제로 등장하는 기사만 남긴다.

이 필터가 없으면 검색어의 일반 단어가 엉뚱한 기사를 물어온다. 실측 예:

| 검색 | 물어온 기사 |
|---|---|
| `MRK capacity expansion sold out` | "What's New at Penn State's Beaver Stadium for 2026?" |
| `MRK pricing power margin expansion` | "Framing Lumber Prices" |
| `GS price increase announcement` | "Smiths Group FY2026 slides" |
| `S-Oil pricing power` | 캐나다 Saturn Oil & Gas 기사 |

전체 수집분의 **60%가 이런 노이즈였다** (163건 중 98건). 필터 적용 후 종목 뉴스 125건이 남았고, 남은 기사는 실제 근거로 쓸 수 있다 — 예: "심텍, 청주 본사에 2742억 투자…소캠 생산 능력 추가 확보"(캐파 공백), "GS 허태수 회장 '혁신 기술로 AI 데이터센터 병목 해소'"(테마 병목).

매칭 규칙:

- 회사명은 부분 문자열로 비교하고, 영문 사명은 토큰으로도 쪼갠다 (`Merck & Company` → `merck`). `Holdings`·`Technologies` 같은 일반어는 토큰에서 뺀다.
- 3글자 이하 티커(`GS`, `MRK`)는 앞뒤가 영숫자가 아닐 때만 인정한다. 한글은 영숫자가 아니므로 `GS리테일` 은 매칭되고 `Smiths Group` 은 걸러진다.
- 제외된 건수는 `news.json` 의 `dropped_irrelevant` 에 기록된다.

필터를 통과한 기사가 없으면 **0건으로 둔다.** 관련 없는 기사 5건을 보여주는 것보다 0건이 정직하다.

#### 사용자 입력은 덮어쓰지 않는다

`fetch_leaders.py` 는 후보 목록만 교체하고 **이미 입력한 조건 체크는 티커 기준으로 보존**한다. 회사명 표기는 사용자가 직접 넣은 경우(`auto_selected` 가 `true` 가 아닌 후보)에만 보존한다 — 자동으로 채운 이름까지 보존하면 이름 정리 로직을 고쳐도 옛 값이 계속 남기 때문이다.

- 후보로 계속 남으면 → 기존 `conditions` 를 그대로 유지
- 후보에서 탈락했는데 입력값이 있으면 → `archived_candidates` 로 이동 (화면 하단에 배지로 표시)
- 탈락했다가 다시 선정되면 → 보관해둔 입력값을 자동 복원

직접 고른 종목을 섞고 싶으면 `manual_inputs.json` 의 `small_wave_candidates` 에 `"auto_selected": false` 로 추가하면 된다. 단, 다음 실행 때 자동 후보로 교체되므로 고정하려면 `leaders.output.also_update_manual_inputs` 를 `false` 로 두고 수동 관리한다.

#### 종목 테이블

| 순위 | 종목 | RS | 초과수익 (3M/6M/12M) | 200일선 | 최근 기사 |
|---|---|---|---|---|---|

`최근 기사` 칸에는 그 종목의 4개 조건 뉴스에서 뽑은 기사 4건이 bullet 으로 들어가고, 각 줄에 조건 태그·매체·발행일과 **[원문]** 버튼이 붙는다.

단순 최신순으로 자르면 한 조건의 기사가 자리를 다 차지하므로, **조건마다 최신 기사를 한 건씩 먼저 뽑고 남는 자리를 최신순으로 채운다.** 기사가 있는 조건이 하나뿐이면 그 조건만 나온다.

> **bullet 은 매체가 단 헤드라인 그대로다.** 기사 본문을 읽고 요약을 생성하지 않는다. 요약을 만들려면 원문을 가져와 재서술해야 하는데, 그 과정에서 없는 내용이 섞일 위험이 있어 하지 않는다. 내용 확인은 `[원문]` 버튼으로 한다.

4개 조건의 체크(✓/✗) 는 테이블에서 빼고 아래 조건별 카드에서 다룬다.

#### 4개 조건은 뉴스 분류용으로만 쓴다

화면에서 조건별 카드(종목 × 조건 40개)와 체크 입력 UI 를 제거했다. 4개 조건은 이제 **뉴스를 분류하는 축**으로만 쓰인다 — `fetch_news.py` 는 여전히 조건별로 검색하고, 그 결과가 테이블 `최근 기사` 칸에 조건 태그와 함께 들어간다.

`manual_inputs.json` 의 `conditions` 필드는 남아 있지만 **화면에서 편집할 수 없다.** 조건 충족 여부를 기록하려면 파일을 직접 편집해야 하며, 현재 대시보드는 그 값을 표시하지 않는다.

#### 조건 체크하기 (파일 직접 편집)

테이블의 `[원문]` 으로 기사를 읽고, `manual_inputs.json` 의 해당 종목 `conditions` 를 직접 편집한다. `value` 는 `true`(충족) / `false`(미충족) / `null`(미입력) 세 가지이며, 근거가 없으면 `null` 로 두는 편이 낫다.

검색 키워드는 `scoring_config.json` 의 `small_wave.conditions[].news_templates` 에서 `{ticker}` / `{company}` / `{company_ko}` 가 치환된다. 업종마다 쓰는 용어가 달라(반도체 "캐파" vs 조선 "슬롯") 결과가 빈약하면 여기를 손보는 게 가장 효과가 크다.

## 6. 뉴스 수집

### 실제로 사용한 경로

**Google News RSS** — 키가 필요 없고 한국어·영어 피드를 모두 지원해 1순위로 채택했으며, 실제 수집도 전량 이 경로로 이뤄졌다.

```
https://news.google.com/rss/search?q={query}&hl={hl}&gl={gl}&ceid={ceid}
  한국어: hl=ko,    gl=KR, ceid=KR:ko
  영어:   hl=en-US, gl=US, ceid=US:en
```

한글 키워드는 한국어 피드에만, 영문 키워드는 영어 피드에만 보낸다. 실패 시 `NEWSAPI_KEY` → `BING_NEWS_KEY` 순으로 폴백하며, 키가 없으면 그 사유를 `news.json` 의 `errors` 에 남기고 **기사를 지어내지 않는다.**

### 원문 URL 해석

Google News RSS 의 링크는 `news.google.com/rss/articles/CBMi…` 형태의 불투명한 리다이렉트다. `fetch_news.py` 는 기사 페이지에서 `data-n-a-sg`(서명)·`data-n-a-ts`(타임스탬프)를 뽑아 Google 의 `batchexecute` 엔드포인트를 호출해 원문 URL로 해석한다. 실패하면 `url_resolved: false` 와 사유를 남기고 **원래 Google 링크를 그대로 유지**한다(브라우저에서는 정상 이동한다).

### 중요도 산식

```
importance_score = 100 × clamp(
    0.40 × 매체티어
  + 0.25 × 키워드적중
  + 0.25 × 최신성
  + 0.10 × 동일사안보도수
, 0, 1)
```

| 요소 | 산출 |
|---|---|
| 매체티어 | 도메인 기반 4단계 (1.00 Reuters/Bloomberg/WSJ/FT/연합뉴스 … / 0.80 CNBC·한경·매경 … / 0.60 / 0.40 / 미등록 0.25) |
| 키워드적중 | 제목 토큰과 검색 키워드 토큰의 교집합 개수 × 0.30 (상한 1.0) |
| 최신성 | `exp(−ln2 × 경과일 / 5)` — 반감기 5일 |
| 동일사안보도수 | 제목 토큰 Jaccard 유사도 ≥ 0.55 로 클러스터링 후, (클러스터 크기 − 1) × 0.34 (상한 1.0) |

산출에 쓰인 모든 항목은 기사별 `importance_basis` 문자열에 그대로 남고, 화면에서 중요도 배지에 마우스를 올리면 툴팁으로 보인다. 가중치는 `scoring_config.json` 의 `news.importance` 에서 조정한다.

**이 산식은 검증되지 않았다.** 매체 티어 목록은 임의로 작성한 것이고, 반감기 5일과 각 가중치에는 근거가 없다.

## 8. 채점 방식

지표 점수는 **−2(매우 부정) ~ +2(매우 긍정)** 정수다. 각 지표는 하나 이상의 *구성요소*를 가지며, 구성요소마다 임계값 테이블과 가중치가 있다.

```
지표점수 = round( Σ(구성요소점수 × 구성요소가중치) / Σ(가중치) )   # −2..+2 로 clamp
```

임계값 테이블은 "값 ≤ max 인 첫 구간"을 택한다. 값이 `null` 이면 그 구성요소는 계산에서 빠지고 남은 구성요소로 재정규화된다.

```
지표기본가중치 = 파도가중치 / 그 파도의 채점 지표 수
정규화가중치   = 지표기본가중치 / Σ(가용 지표의 기본가중치)
종합점수       = (Σ(지표점수 × 정규화가중치) + 2) / 4 × 100
커버리지       = 가용 채점 지표 수 / 전체 채점 지표 수
```

커버리지가 60% 미만이면 종합 점수를 내지 않고 "데이터 부족 — 판단 유보" 를 띄운다.

### 비중 매핑

| 종합 점수 | 투자 | 현금 | 구간 |
|---|---|---|---|
| 0–20 | 20% | 80% | 강한 방어 |
| 20–40 | 40% | 60% | 방어 |
| 40–60 | 60% | 40% | 중립 |
| 60–80 | 80% | 20% | 공격 |
| 80–100 | 90% | 10% | 강한 공격 |

전부 `scoring_config.json` 의 `allocation_map` 에서 수정할 수 있다. **규칙 기반 참고치이며 투자 권유가 아니다.**

### 임계값 근거 확인

각 지표 카드의 점수 배지에 마우스를 올리면 구성요소별 값·점수·가중치·임계값 테이블·설정에 적힌 근거 문장이 전부 툴팁으로 나온다. 종합 점수에 실제로 반영된 재정규화 가중치도 함께 표시된다.

## 9. 수동 입력

브라우저는 로컬 파일에 쓸 수 없다. 대시보드는 **복사 가능한 JSON 스니펫**을 만들어 주고, 사용자가 `manual_inputs.json` 에 붙여넣는 방식이다.

1. 뉴스 패널에서 근거 기사 옆 **"이 기사를 근거로 점수 입력"** 버튼을 누른다 (해당 지표 카드가 하이라이트되고 입력 창이 열린다).
2. 점수(−2 ~ +2), 근거 URL, 메모를 넣는다.
3. 생성된 JSON을 복사해 `manual_inputs.json` 의 해당 위치에 붙여넣는다.
4. 페이지를 새로고침하면 점수가 반영되고 커버리지가 올라간다.

## 10. 알려진 한계

- **임계값과 가중치에 실증 근거가 없다.** 전부 초기 가정값이며 백테스트되지 않았다. 사용 전 조정 필요.
- **종목 뉴스가 비어 있는 조건이 많다.** 관련성 필터를 통과한 기사가 40개 조건 중 16개에서 0건이다. 특히 이름이 짧거나 흔한 종목(MRK 0건, S-Oil 1건)이 그렇다. 검색어가 종목을 특정하지 못하기 때문이며, `scoring_config.json` 의 `news_templates` 에 그 종목 고유의 제품·공장·고객사 이름을 넣으면 개선된다.
- **뉴스 발행일이 최대 하루 어긋날 수 있다.** Google News RSS 의 `pubDate` 가 매체 자체 발행 시각과 다른 경우가 있다 (시간대 처리 차이). 일부 기사는 시각이 `07:00:00 UTC` 로 뭉뚱그려 들어온다.
- **유료 기사는 링크 확인이 불가하다.** Reuters·FT 등은 자동 요청에 401/403 을 반환한다. 링크 자체는 유효하며 브라우저에서는 열린다.
- **RRP 변화율은 해석에 주의해야 한다.** 잔고가 0 근처까지 내려온 상태라 퍼센트 변화가 극단적으로 튄다. 카드의 절대 수준을 함께 볼 것.
- **Sahm rule 갭은 결측월이 있으면 일부 창을 건너뛴다.** `UNRATE` 에 결측월이 있는 경우 해당 3개월 창을 계산에서 제외하고, 제외한 창 수와 결측월을 카드에 표시한다.
- **뉴스 본문 요약(snippet)은 제공되지 않는다.** Google News RSS 의 `description` 은 기사 제목과 매체명을 반복할 뿐이어서, 제목과 사실상 동일한 경우 빈 문자열로 처리한다(현재 수집분은 전부 여기에 해당). 내용을 보려면 제목 링크로 원문을 열어야 한다.
- **"모멘텀 상위 = 주도주"라는 전제 자체가 검증되지 않았다.** RS 모멘텀은 후행 지표라 추세가 꺾일 때 가장 늦게 반응한다. 선정 결과는 후보일 뿐이며, 4개 조건을 사람이 확인하지 않으면 아무 의미가 없다.
- **가격 시계열 왜곡을 완전히 걸러내지 못한다.** 백분위 방식으로 이상치의 지배력은 줄였지만, 스핀오프·액면병합·재상장 종목의 장기 수익률은 여전히 부정확하다. 상위권에 낯선 종목이 보이면 12개월 수익률이 비정상적으로 큰지 먼저 확인할 것.
- **yfinance 는 비공식 경로다.** Yahoo 가 응답 형식을 바꾸거나 차단하면 깨진다. 직접 호출하면 즉시 429가 뜨지만 yfinance 는 세션을 관리해 동작한다 — 이 스크립트를 고칠 때 순수 `urllib` 로 대체하지 말 것.
- **순위 모집단이 시가총액 상위 100종목이다.** 중소형 테마주가 아무리 급등해도 구조적으로 후보에 오르지 않는다. 대형 주도주를 잡기 위한 의도적 선택이며, 초기 국면의 소형주를 보려면 `rank_universe_top_by_cap` 을 올리거나 `null` 로 두면 된다 — 다만 그러면 상위권이 소형주로 채워진다(실측 결과 삼성전자 #67).
- **작은 파도 4개 조건은 화면에서 다루지 않는다.** 자동화는 후보 선정과 조건별 근거 기사 수집까지이며, 조건 충족 여부를 기록·표시하는 UI 는 없다. 기사를 읽고 판단하는 일은 전적으로 사용자 몫이다.
- **기사 요약은 헤드라인이다.** 테이블의 bullet 은 매체 헤드라인 그대로이며 본문을 요약한 것이 아니다. 헤드라인만으로 조건 충족을 판단하지 말고 `[원문]` 을 열어 확인할 것.
- **네이버 금융·Nasdaq 스크리너 모두 비공식 엔드포인트다.** 공개돼 있고 키가 필요 없지만 언제든 형식이 바뀔 수 있다. 유니버스 수집이 실패하면 순위는 보류된다.
- **선행성 측정 구간은 20년(2006~)이고 침체는 2회뿐이다.** 독립 표본이 사실상 연 단위 개수라 상관계수 자체를 신뢰해선 안 된다. 5년 구간에서 강했던 유동성 지표들이 20년에서 0으로 무너진 것이 그 증거다.
- **종합점수 시계열은 역산값이다.** 과거 기록이 아니라 지금의 자료·임계값으로 다시 계산한 값이므로 성과 검증에 쓸 수 없다. 실제 이력을 남기는 적립 로그는 아직 없다.
- **선정은 실행 시점의 스냅샷이다.** 과거 선정 이력을 보관하지 않으므로 "언제 편입/탈락했는지" 추적이 안 된다.
- **단일 사용자 로컬 도구다.** 인증·다중 사용자·이력 저장 기능이 없다. `data.json` 은 실행할 때마다 덮어쓰이며 과거 스냅샷을 보관하지 않는다.
